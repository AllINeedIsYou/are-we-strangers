# Контракт фронта и FastAPI

К существующему FastAPI подключены авторизация, поиск пользователей, создание и список чатов, история и отправка текстовых сообщений, доставка через WebSocket. Медиа и механики истории знакомства остаются отдельным демо.

## Подключённая авторизация

Фронт обращается к `/api/auth/*` с `credentials: include`. Vite и Vite Preview проксируют `/api` на `http://127.0.0.1:8000`; другой адрес можно задать серверной переменной `AWS_API_TARGET`. Для опубликованного фронта нужен такой же маршрут через сервер/обратный прокси либо отдельно согласованная настройка CORS и cookie.

| Метод | Путь | Запрос и ответ |
| --- | --- | --- |
| POST | /api/auth/login | `{login, password}` → UserResponse и HttpOnly cookie `session_token` |
| GET | /api/auth/me | Cookie → UserResponse; 401 означает отсутствие действующей сессии |
| POST | /api/auth/logout | Отзыв текущей сессии и удаление cookie; 204 без тела |
| POST | /api/auth/register | `{phone, email, name, username, password}` → `{user, verification_token, verification_expires_at, telegram_url}`; вход ещё не выполнен |
| POST | /api/auth/resend-phone-verification | `{phone, password}` → новая ссылка и заявка подтверждения |
| POST | /api/auth/verify-phone | `{verification_token, code}` → UserResponse; затем отдельный вход по паролю |
| POST | /api/auth/request-email-verification | Cookie, без тела → `{expires_at}`; 409 — уже подтверждена, 429 — повторный запрос раньше минуты, 502 — ошибка отправки |
| POST | /api/auth/verify-email | `{token}` → UserResponse; подтверждение не создаёт сессию входа |

Username при регистрации вводится после статичного `@`, отправляется без `@`, хранится сервером с `@`. Максимум 31 символ без префикса. Регистр сохраняется. Вход по username требует `@`; также доступны почта и телефон. Пароль передаётся без преобразований. Фронт не сохраняет пароли и токены входа в localStorage/sessionStorage.

Экран `/verify-email?token=...` читает токен в память и убирает его из адресной строки. Подтверждение выполняется по явному нажатию кнопки через POST, а не при открытии ссылки. Ошибки API показываются в форме; сетевой сбой не трактуется как успешный вход. Восстановление пароля ещё не реализовано на сервере.

На локальном HTTP существующий сервер ставит `secure=False`, срок cookie и сессии — 30 дней. Для HTTPS-публикации серверу потребуется `secure=True`. Локальная демонстрация и метаданные аватара изолированы по ID аккаунта (`aws.demo.v1.user.{id}`, `aws.avatar.user.{id}`). Изменение имени и серверная загрузка аватара ещё не подключены.

## Подключённая переписка

| Метод | Путь | Запрос и ответ |
| --- | --- | --- |
| GET | /api/user/search?q=… | Частичный регистрозависимый поиск по `@username` или точный поиск полного телефона → массив `{id, name, username}`, максимум 20 для username |
| GET | /api/chats | Массив `{id, created_at, partner: {id, name, username}}` |
| POST | /api/chats | `{partner_id}` → существующий или новый диалог в том же формате |
| GET | /api/chats/{chat_id}/messages?before_id=… | Последние 50 сообщений до ID, либо последние 50 без курсора; массив в хронологическом порядке |
| POST | /api/chats/{chat_id}/messages | `{text}` → сохранённое сообщение, 201 |
| WS | /api/ws | Cookie `session_token`; сервер присылает `{type: "connected", user_id}`; `{type: "ping"}` → `{type: "pong"}` |

Сообщение сервера: `{id, chat_id, sender_id, text, created_at}`. После commit сервер отправляет обоим участникам, во все их подключения, `{type: "message.created", message: MessageResponse}`. Направление сообщения выводится из `sender_id`, время и разделители дней — из `created_at`. Максимум 4096 символов; текст передаётся без обрезки и изменения форматирования, пустое по содержанию сообщение не отправляется.

Все HTTP-запросы используют `credentials: include`. WebSocket открывается на том же origin (`ws:` для HTTP, `wss:` для HTTPS), браузер передаёт cookie сам. Vite Dev и Preview проксируют `/api` с поддержкой WebSocket (`ws: true`), включая upgrade на `/api/ws`. Токены не передаются в URL или localStorage.

Поиск по имени работает только среди своих чатов, без запроса глобального поиска. При вводе `@username` или телефона показываются два раздела: «Мои чаты» и «Глобальный поиск». Username сопоставляется по префиксу с сохранением регистра. Для номера существующий диалог определяется по ID пользователя из точного результата API: публичный профиль не раскрывает телефон. Из глобальных результатов фронт исключает пользователей, с которыми уже есть чат, по partner ID. Запрос задерживается на 250 мс после ввода; предыдущие запросы отменяются, устаревшие результаты не показываются. Сам пользователь исключён из результатов. На телефоне открытие результата переводит к переписке; на компьютере переписка остаётся рядом со списком.

POST-ответ и WS-событие объединяются по серверному ID. В UI появляются только подтверждённые сервером сообщения. При ошибке текст остаётся в поле; автоматического повтора POST нет: сервер ещё не поддерживает `client_id` и идемпотентность, а при потере ответа сообщение уже могло сохраниться. Перед ручным повтором предлагается проверить историю.

При разрыве WS используется повторное подключение с задержкой 1, 2, 4, 8, максимум 15 секунд. Ping каждые 20 секунд и ожидание pong до 10 секунд позволяют обнаружить зависшее соединение. После `connected`, возврата во вкладку и восстановления сети список и история перечитываются. Для пропуска более 50 сообщений страницы загружаются назад до последней завершённой точки сверки; новые live-события не сдвигают эту точку преждевременно. Старые загруженные страницы сохраняются в памяти. Загрузка более ранних сообщений сохраняет положение прокрутки. Полного журнала событий/replay на сервере пока нет.

При выходе или смене аккаунта соединение закрывается, запросы отменяются, поздние результаты игнорируются. HTTP 401 возвращает к входу; сбой сети сохраняет переписку и показывает ошибку. Сервер проверяет сессию при установке WS, но пока не закрывает уже открытые подключения при истечении/отзыве сессии — это отдельная задача бэка.

Список чатов сервера не содержит последнего сообщения, поэтому фронт получает последние страницы для превью (не более трёх запросов истории одновременно). Время активности собеседника неизвестно: вместо выдуманного online показывается username. Одна галочка означает «сохранено на сервере», а не прочитано. Счётчик новых сообщений локальный, не серверный read/unread. Поиск внутри чата работает по загруженной истории, это явно подписано. Новые входящие события запускают уведомление звезды с cooldown 2,5 секунды; догрузка истории вспышек не вызывает.

Реальные чаты живут в памяти и загружаются из API; они не подменяются демо при ошибке. Отдельная кнопка «Демо» открывает прежний визуальный макет и локальные механики. Данные демо остаются изолированы по ID аккаунта. В реальном режиме неподключённые операции недоступны: ответ цитатой, редактирование, удаление, закрепление, пересылка, моменты, главы, медиа и записи. Копирование, выбор и поиск по загруженным сообщениям доступны.

## Следующие блоки — предложения для согласования

| Метод | Путь | Назначение |
| --- | --- | --- |
| PATCH | /api/messages/{id} | Изменение собственного сообщения |
| DELETE | /api/messages/{id} | Удаление со scope self/everyone |
| POST/DELETE | /api/chats/{id}/pins/{message_id} | Закрепление и открепление |
| POST | /api/chats/{id}/forward | Пересылка с исходным автором |
| POST | /api/chats/{id}/read | Серверные статусы прочтения |
| POST | /api/attachments | Загрузка медиа |
| GET/POST | /api/chats/{id}/moments | Моменты из нескольких сообщений |
| GET/POST | /api/chats/{id}/questions | Вопросы в будущее |
| GET/POST | /api/chats/{id}/chapters | Предложение новой главы |
| POST | /api/chapters/{id}/accept | Подтверждение второго участника |

Нужно согласовать `client_id` для идемпотентной отправки, цитаты, серверные статусы и события изменения/удаления. Текущий менеджер подключений хранится в памяти одного процесса: для нескольких workers/инстансов потребуется общая доставка событий. При публикации нужен прокси с WebSocket upgrade, HTTPS и secure cookie; междоменные credentials/CORS/CSRF обсуждаются отдельно.

## Контракт медиа

Asset: `{id, kind: photo|voice|circle|video|file, mime, size, name, duration, url}`. Сейчас `id` — ключ Blob в IndexedDB, а `url` создаётся временно и отзывается при размонтировании. После подключения API: загрузить Blob multipart, получить серверный asset_id и постоянный авторизованный URL, затем отправить сообщение с asset_ids. Нельзя пересылать blob: URL на другое устройство. Сервер проверяет действительный формат, размер, принадлежность к чату и доступ к скачиванию.

Кружок и голосовое записываются через MediaRecorder в поддерживаемом браузером WebM/Opus либо MP4/AAC; учитывать mime вместо предположения о расширении. Момент должен хранить массив снимков сообщений и ссылок на медиа. Сервер не удаляет физический файл, пока на него ссылаются моменты, пересылки или восстановимые сообщения. Удаление scope=everyone синхронизируется отдельным событием WebSocket; локальный журнал прототипа этого не делает.


Аватар пока обрезается пользователем и хранится в IndexedDB; серверной загрузки ещё нет. Уведомление ограничено кулдауном 2500 мс, который не продлевается во время частых сообщений. Анимация удаления завершает представление, затем применяет уже выбранный `scope`; итоговую доставку удаления другому пользователю обеспечивает сервер.
