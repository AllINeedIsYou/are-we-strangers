# Предлагаемый контракт для FastAPI

Черновик для согласования. Прототип сейчас работает полностью локально, к этим маршрутам не обращается.

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | /api/auth/login | `{login, password}` → сессия через HttpOnly Secure cookie + пользователь |
| POST | /api/auth/register | Создание пользователя; правила согласуем |
| POST | /api/auth/logout | Завершение сессии |
| GET | /api/me | Текущий пользователь |
| GET | /api/chats | Участники, последнее сообщение, unread, online |
| GET | /api/chats/{id}/messages?before={cursor}&limit=50 | Страница истории: `{items, next_cursor}` |
| POST | /api/chats/{id}/messages | `{client_id, text, attachment_ids}` → Message |
| PATCH | /api/messages/{id} | Изменение собственного `{text}` → Message с edited_at |
| DELETE | /api/messages/{id} | Удаление `{scope: self | everyone}`; права и срок восстановления проверяет сервер |
| POST/DELETE | /api/chats/{id}/pins/{message_id} | Закрепление / открепление |
| POST | /api/chats/{id}/forward | `{message_ids, client_id}` → сообщения с автором оригинала |
| POST | /api/chats/{id}/read | `{last_message_id}` |
| POST | /api/attachments | Загрузка multipart → id, имя, mime, размер, URL |
| GET/POST | /api/chats/{id}/moments | Момент: `{message_ids, reason}`; снимки сообщений и медиа |
| POST | /api/moments/{id}/response | Ответ второго участника `{text}` |
| GET/POST | /api/chats/{id}/questions | Вопрос `{text, opens_at}` |
| POST | /api/questions/{id}/answers | Собственный `{text}` после opens_at |
| GET/POST | /api/chats/{id}/chapters | Предложение `{title}`; статус pending |
| POST | /api/chapters/{id}/accept | Согласие второго участника, маркер в истории |
| WS | /api/events | message.created, message.read, chat.updated, moment.updated, question.opened, chapter.accepted |

Все даты сервера — ISO 8601 UTC; UI отображает местное время. Сообщение: `{id, client_id, chat_id, sender_id, text, created_at, attachments, read_at, edited_at, reply_to, forwarded_from, pinned}`. Не использовать `own` и отформатированное `time` как источник истины: UI выводит их из sender_id / created_at.

Отправка должна быть идемпотентной по client_id. Статусы сообщения: sending → sent → read либо failed с повтором. Галочки макета пока демонстрационные. Проверять принадлежность к чату на каждом маршруте. Сервер подтверждает согласие другого участника на новую главу; история при этом не удаляется. Демо-кнопки моделирования ответов в production убираются.

При WebSocket reconnect: backoff, восстановление с последнего event_id, дедупликация по id/client_id. Не проигрывать анимацию звезды для всей догруженной истории. Для новых уведомлений: одна вспышка, cooldown 2,5 секунды без отложенной очереди.

Если фронт и API на разных доменах, согласовать CORS с точным origin и credentials, SameSite cookies и CSRF-защиту для изменений. Секретов и токенов в Vite-переменных нет.

Ответ хранит reply_to_id и снимок цитаты (автор/текст), чтобы исходное сообщение можно было удалить без потери смысла ответа. Редактирование разрешает только автор; сервер повторяет проверку, а не полагается на скрытую кнопку UI. Пересылка сохраняет исходного автора и создаёт новое сообщение, не копирует закрепление и ссылку на цитату из другого чата. Для удаления и отмены нужен согласованный серверный период восстановления; текущая отмена работает только в памяти браузера.

## Контракт медиа

Asset: `{id, kind: photo|voice|circle|video|file, mime, size, name, duration, url}`. Сейчас `id` — ключ Blob в IndexedDB, а `url` создаётся временно и отзывается при размонтировании. После подключения API: загрузить Blob multipart, получить серверный asset_id и постоянный авторизованный URL, затем отправить сообщение с asset_ids. Нельзя пересылать blob: URL на другое устройство. Сервер проверяет действительный формат, размер, принадлежность к чату и доступ к скачиванию.

Кружок и голосовое записываются через MediaRecorder в поддерживаемом браузером WebM/Opus либо MP4/AAC; учитывать mime вместо предположения о расширении. Момент должен хранить массив снимков сообщений и ссылок на медиа. Сервер не удаляет физический файл, пока на него ссылаются моменты, пересылки или восстановимые сообщения. Удаление scope=everyone синхронизируется отдельным событием WebSocket; локальный журнал прототипа этого не делает.


Обновление интерфейса: регистрация ожидает `phone`, `email`, `name`, `username`, `password`. Прототип сохраняет только непарольные поля локально; серверу предстоит валидация/подтверждение контактов. Аватар — файл изображения через отдельный upload с получением media id/URL; локальная версия хранит центральный квадрат 512×512 в IndexedDB. UI использует `aws.avatar` для метаданных своего аватара. Уведомление ограничено кулдауном 2500 мс, который не продлевается во время частых сообщений. Анимация удаления завершает представление, затем применяет уже выбранный `scope`; итоговую доставку удаления другому пользователю обеспечивает сервер.
